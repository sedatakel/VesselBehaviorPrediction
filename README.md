# AIS-Based Vessel Behavior Prediction for Port Traffic Safety and Collision-Avoidance Early Warning

This repository contains the notebooks and paper artifacts for an AIS-based vessel behavior prediction study. The project converts raw Automatic Identification System (AIS) vessel messages into fixed 10-minute vessel-time slices and classifies each slice into one of five operational behavior states:

- `steady`
- `stop`
- `accelerate`
- `decelerate`
- `maneuver`

The final model uses a leakage-aware, inference-safe feature matrix and evaluates performance with an MMSI-held-out split so that validation and test vessels are not present in the training set.

## Project Summary

The study uses two AIS datasets:

- **DS1** is used for exploratory data analysis and data-quality investigation.
- **DS2** is used for final preprocessing, feature engineering, model training, evaluation, and reporting.

The final DS2 pipeline starts from **482,846 raw AIS messages**, constructs a continuous 10-minute vessel-time representation over **424 MMSIs**, and produces **91,021 model-ready labeled samples** with **48 current/past-only model features**.

The final selected model is **XGBoost**. In the strict raw-ML configuration, without rule-based inference overrides, the final model achieves:

| Metric | Test Score |
|---|---:|
| Accuracy | 0.9492 |
| Balanced Accuracy | 0.7806 |
| Macro F1 | 0.7314 |
| Weighted F1 | 0.9505 |

Rule-signature diagnostics are used only for post-hoc error analysis and feature-design interpretation. They are not part of the final deployable inference path.

## Data Source

The AIS data are based on publicly available vessel traffic data from MarineCadastre.gov / NOAA AIS vessel traffic data.

The final DS2 dataset used in the modeling pipeline is a January 2024 AIS extract from the southern Louisiana / Gulf Coast region with the following observed coverage:

| Field | Value |
|---|---|
| Observed timestamp range | 2023-12-31 00:00:00 to 2024-01-30 23:59:57 |
| Longitude range | -90.35356 to -90.07744 |
| Latitude range | 29.00183 to 29.11970 |
| Raw AIS messages | 482,846 |
| Raw columns | 17 |
| Unique MMSIs | 424 |
| Raw CSV size | approximately 51.95 MiB |

## Notebook Descriptions

### `AIS_DS1_EDA.ipynb`

This notebook performs exploratory data analysis on DS1. It investigates AIS-specific data quality issues and motivates later preprocessing decisions.

Main checks include:

- raw row and column counts
- unique MMSI count
- timestamp coverage
- AIS reporting gaps
- heading placeholder values
- suspicious COG boundary values
- missing static vessel fields
- SOG distribution and outlier checks
- preview of the 10-minute slice representation
- final 48-feature preview/audit alignment with the DS2 pipeline

### `AIS_DS2_Preprocessing_Data_Preparation.ipynb`

This notebook prepares the final DS2 modeling dataset.

Main steps include:

- loading and cleaning raw AIS data
- sorting by MMSI and timestamp
- constructing 10-minute vessel-time slices
- calculating representative slice-level movement features
- deriving rule-based behavior labels
- creating current/past-only model features
- masking unreliable low-speed COG-derived variables
- excluding future-window features from the model matrix
- performing MMSI-held-out train/validation/test splitting
- applying train-only class balancing
- exporting prepared datasets and feature metadata

The preprocessing notebook produces the final 48-feature dataset used by the training/evaluation notebook.

### `AIS_DS2_Model_Training_Evaluation.ipynb`

This notebook trains and evaluates the final classifiers.

Main steps include:

- loading the prepared DS2 exports
- verifying the 48-feature inference-safe feature matrix
- training baseline tabular models
- selecting XGBoost as the final classifier
- evaluating on MMSI-held-out validation and test sets
- reporting strict raw-ML test performance
- generating class-level metrics
- generating confusion matrix heatmap
- generating threshold diagnostics
- generating feature-importance outputs
- performing rule-signature diagnostics for post-hoc error interpretation

## Feature Engineering Summary

The final model uses **48 current/past-only features**. Future-window variables are used only for target construction and offline diagnostics; they are not included in `X_train`, `X_valid`, or `X_test`.

Key feature groups include:

- current slice state features
- lagged slice state features
- past motion-change features
- rolling local-context features
- stability features
- reliability and time features
- inference-safe behavior trend features

Two important inference-safe behavior features are included:

- `stop_tendency_score`: captures whether current speed is lower than recent rolling speed.
- `maneuver_intensity_score`: captures recent course-change intensity while respecting COG reliability.

The diagnostic flag `is_moving_steady_candidate` is not used as a final model feature.

## Target Classes

The final behavior classes are:

| Class | Meaning |
|---|---|
| `steady` | Stable moving behavior |
| `stop` | Stopped or near-stopped behavior |
| `accelerate` | Positive speed-transition behavior |
| `decelerate` | Negative speed-transition behavior |
| `maneuver` | Significant course-change behavior |

The target labels are rule-derived because raw AIS data do not provide clean supervised behavior labels for these five classes. Target construction can use future windows to define labels, but the final model features use only current and past information.

## Evaluation Design

The evaluation uses an **MMSI-held-out split**. This prevents slices from the same vessel appearing in both training and validation/test sets.

Final split summary:

| Partition | Samples | Unique MMSIs |
|---|---:|---:|
| Original train before balancing | 60,365 | 274 |
| Validation | 16,096 | 59 |
| Test | 14,560 | 59 |
| Balanced training set used for fitting | 6,625 | train-only balanced sample |

Only the training set is balanced. Validation and test remain naturally imbalanced.

## Final Test Results

The final deployable result is the strict raw-ML XGBoost model without rule overrides.

| Metric | Test Score |
|---|---:|
| Accuracy | 0.9492 |
| Balanced Accuracy | 0.7806 |
| Macro Precision | 0.6972 |
| Macro Recall | 0.7806 |
| Macro F1 | 0.7314 |
| Weighted F1 | 0.9505 |

Class-level F1 scores:

| Class | F1 Score |
|---|---:|
| steady | 0.7289 |
| stop | 0.9909 |
| accelerate | 0.7444 |
| decelerate | 0.6961 |
| maneuver | 0.4965 |

The stop class is recognized very strongly. Maneuver remains the most difficult class because maneuver evidence often overlaps with acceleration and deceleration patterns in short 10-minute windows.

## Reproducibility Instructions

### 1. Clone the repository

```bash
git clone <repository-url>
cd <repository-name>
```

### 2. Create a Python environment

A Python 3.10+ environment is recommended.

```bash
python -m venv .venv
source .venv/bin/activate      # macOS/Linux
# .venv\Scripts\activate       # Windows
```

### 3. Install dependencies

The notebooks use common Python data science libraries. Install the required packages with:

```bash
pip install pandas numpy matplotlib scikit-learn xgboost joblib
```

If your environment is missing notebook support:

```bash
pip install jupyter
```

### 4. Prepare the data folder

Place the raw DS2 CSV file at:

```text

```

If the raw AIS file is not committed to the repository, download the matching MarineCadastre.gov / NOAA AIS extract and subset it according to the DS2 temporal and spatial coverage described above.

### 5. Run notebooks in order

Run the notebooks in this order:

```text
1. notebooks/AIS_DS1_EDA.ipynb
2. notebooks/AIS_DS2_Preprocessing_Data_Preparation.ipynb
3. notebooks/AIS_DS2_Model_Training_Evaluation.ipynb
```

The preprocessing notebook creates the prepared data directory:

```text
ais_ds2_prepared/
```

The training/evaluation notebook reads from this generated directory.

## Notes on Leakage Prevention

This project explicitly separates:

1. **Target construction signals**
   These may use future windows to define supervised labels.

2. **Deployable model features**
   These use only current and past AIS-derived information.

3. **Post-hoc diagnostics**
   These are used only to analyze structured errors and are not used as final inference-time overrides.

This separation is central to the credibility of the reported strict raw-ML result.
